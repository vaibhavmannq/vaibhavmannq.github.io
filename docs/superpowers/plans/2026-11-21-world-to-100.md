# The night's walk at 100 % (M8.6): Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> **This project:** inline execution (owner, s11 onward), terse chat; each task closes with a commit, a % verdict and its numbers in the ledger.

**Goal:** every place at 100 % in all five views on low and high, and every ride a smooth, planned shot with no dead stretch,
inside relaxed limits (≈ 60 MB, a lantern loading experience) and at 60 fps.

**Architecture:** Phase 0 builds the measuring tools (journey motion, dead share, GPU ceiling) and the three structural
pieces the later phases fill: the lantern loader, the far layer that is always drawn, and close-up sets streamed and
compiled inside passages. Phases 1–3 then lift the eight causes and each place on top of those pieces; Phase 4 judges
the whole night. Phases 1–4 are written in detail at their own start, from Phase 0's numbers (the budgets they size
content to do not exist yet).

**Tech Stack:** three.js r186 (WebGPU, WebGL2 fallback), TSL, TypeScript 7, Vite 8, Vitest 5, Playwright 1.63 (quiet
Chrome, phone over CDP), Blender + Python tools in `tools/world/`.

**Spec:** `docs/superpowers/specs/2026-11-21-world-to-100-design.md` (D53). Also binding: Amendment 1, D1–D52.

**Ledger:** `docs/handover/ledgers/2026-11-21-world-to-100.md` (rulings from R208). **Check scripts:** `.superpowers/w100/`.

## Global Constraints

- 60 fps at low on this laptop at every stop and through every ride; phone 60 fps at mid/high (D18, R198).
- Download ≈ 60 MB in all; ≈ 10 MB before the first place; the rest during rides (D53).
- The name on screen < 1 s; the lantern experience 5–15 s on a first visit, ≈ 2 s when everything is cached (spec §4.1).
- No fixed material/draw caps; whatever holds the frame rate, measured (D53 replaces D13's caps).
- R38 is law: every part compiled for the eye and the mirror before it shows; cold rides measure 0 late pipelines.
- Anti-goals: no stutter on a ride, no visible pop-in, the whole coast visible from high places, no loader that feels like waiting.
- No stills or painted backdrops (D50); look-around stays ±40° / ±15° (D27).
- Whole-world changes (sea, sky, light) checked at all nine stops and every ride before the owner sees them (D47).
- Speed verdicts from a whole-night gpu-sweep old vs new, run alone (s26); one test browser at a time, quiet (`.superpowers/quiet-browser.mjs`).
- No git stash; never push without asking; no AI attribution in commits.

## Review Focus

1. **A visitor rides backwards** (Prev, scroll up, the rail): the place behind must have its set or a clean far version, never an empty place. → Task 4 test `wantedSets going back keeps the previous place`.
2. **A visitor jumps** (rail click, `?stop=`, a fast flick across three places): the set is not prefetched; the place must show its far version and swap the set in behind a fade, not hitch. → Task 4 test `a jump with no prefetch asks for the target at once`; Task 5 test `a jump swaps behind the fade`.
3. **Reduced motion** (no flights, a cross-fade): no passage exists; the swap must happen behind the cross-fade. → Task 5 test `reduced motion swaps at the fade's midpoint`.
4. **A slow or failing network during the lantern**: the lantern must not hang; a cap moves on to the journey with whatever is ready, a hard failure goes to the stills path. → Task 6 tests `the lantern gives up waiting at the cap` and `a failed base load ends in stills`.
5. **Storage blocked** (private mode, sessionStorage throws) for the returning-visitor skip: the loader runs as a first visit and never throws. → Task 6 test `blocked storage counts as a first visit`.
